**Using `.prettierrc.ts` is generally considered over-engineering.**

1. **Runtime Complexity:** Prettier runs in a Node.js environment. Since Node.js does not handle TypeScript configuration files natively without specific loaders (like `ts-node`) or experimental flags, using `.ts` introduces unnecessary dependencies and potential runtime errors.
2. **Editor Incompatibility:** The Prettier VS Code extension frequently fails to load `.ts` configurations because it runs in an isolated context. As a result, your CLI might work, but **"Format on Save" in the editor will break.**
3. **A Simpler Solution Exists:** You can achieve the **exact same type safety and IntelliSense** in a standard `.js` file using JSDoc (`/** @type {import('prettier').Config} */`), while ensuring instant speed and universal compatibility.
